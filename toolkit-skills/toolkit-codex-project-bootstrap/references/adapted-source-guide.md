# 适配后的来源指南

# 项目引导 - 快速创建 Codex 配置

为当前工作目录生成 Codex 所需的配置文件，让 Codex 从第一轮对话就理解项目全貌，避免盲目扫描浪费 Token。

## 执行流程

按以下顺序执行，每一步都依赖上一步的结果：

### 第 1 步：检查全局 AGENTS.md

检查 `~/.claude/AGENTS.md` 是否存在：

- **存在** → 告知用户已有全局配置，简要展示内容摘要，跳到第 2 步
- **不存在** → 进入全局配置创建流程（见下方"全局 AGENTS.md 生成指南"），创建完成后再继续

### 第 2 步：分析当前项目

通过以下方式自动识别项目特征（不要询问用户，直接探测）：

1. **项目类型识别** — 读取根目录文件判断：
   - `pom.xml` 存在 → Java/Maven 项目，提取 groupId、artifactId、Java 版本、Spring Boot 版本、模块列表
   - `build.gradle` 存在 → Java/Gradle 项目
   - `package.json` 存在 → Node.js 前端项目，提取依赖框架（Vue/React/Angular）、构建工具
   - `requirements.txt` / `pyproject.toml` 存在 → Python 项目
   - `go.mod` 存在 → Go 项目
   - `Cargo.toml` 存在 → Rust 项目
   - 以上都不存在 → 通用项目

2. **目录结构扫描** — 只扫描第一层和第二层目录（不要递归深入），记录：
   - 源代码目录（src/、app/、lib/ 等）
   - 配置目录（config/、settings/ 等）
   - 文档目录（doc/、docs/ 等）
   - 前端目录（front/、web/、client/ 等）
   - 测试目录（test/、tests/、__tests__/ 等）
   - 构建输出目录（target/、dist/、build/、out/ 等）
   - 依赖目录（node_modules/、vendor/ 等）

3. **代码规范推断** — 检查是否存在：
   - `.editorconfig` → 代码风格配置
   - `.eslintrc*` / `eslint.config.*` → JS/TS 规范
   - `checkstyle.xml` → Java 规范
   - `.prettierrc*` → 格式化配置
   - `tsconfig.json` → TypeScript 配置

### 第 3 步：检查现有项目级配置

检查当前目录是否已有：
- `AGENTS.md` — 存在则询问用户是否覆盖
- `.gitignore` — 存在则询问用户是否覆盖

如果用户选择不覆盖，跳过对应文件的生成。

### 第 4 步：生成项目级 AGENTS.md

根据第 2 步的分析结果，使用以下模板生成。注意：
- 所有引用的目录和文件必须实际存在，不存在则不要写入
- 如果项目同时包含前后端，都要覆盖
- 保留用户可能已有的文档引用路径

#### 模板

```markdown
# {项目名称} 项目指南（{技术栈概要}）

## 项目概述

{1-2 句话描述项目是什么、做什么}

## 技术栈

### 后端 {如果存在}
- {Java 版本}，{框架}（{关键版本信息}）
- {构建工具}，{数据库}，{连接池}
- 模块：{列出核心模块名}

### 前端 {如果存在}
- {框架}（{构建工具} 构建），目录：{前端目录}
- {关键依赖说明}

## 目录结构

{使用树形结构，只列出前两层，附简短注释}

## 代码规范

### 后端 {如果存在}
- {规范名称，如：阿里巴巴Java开发规范}
- {分层架构说明}
- {API 路径约定}
- {Lombok / 事务等工具约定}

### 前端 {如果存在}
- {API 风格，如：Composition API}
- {组件命名约定}
- {图表/状态管理等约定}

## Token 优化指令

### 优先读取的目录
- {按角色列出关键路径}

### 不要读取的目录
- {列出构建输出、依赖、IDE 等目录}

### 工作原则
- 每次只专注于一个模块，不要扫描整个项目
- 前后端修改互不干扰
- 使用 /compact 定期压缩上下文
- 复杂任务委托给子 Agent 处理
```

### 第 5 步：生成 .gitignore

根据项目类型自动生成忽略规则。核心原则：**排除一切 Codex 不需要读取的内容**。

#### 基础规则（所有项目都包含）

```
# 编译/构建输出
target/
dist/
build/
out/

# 依赖
node_modules/
vendor/

# Git 元数据
.git/

# IDE
.idea/
.vscode/
*.iml

# 操作系统
.DS_Store
Thumbs.db

# 日志
*.log

# 打包产物
*.jar
*.war
*.zip
*.tar.gz

# 临时文件
*.tmp
*.swp
```

#### 按项目类型追加

- **Java/Maven** → 追加 `*.class`
- **Node.js** → 追加 `.cache/`、`.nuxt/`、`.next/`
- **Python** → 追加 `__pycache__/`、`*.pyc`、`.venv/`
- **Go** → 追加 `*.exe`

### 第 6 步：验证

生成完成后，执行以下验证：

1. **路径验证** — AGENTS.md 中引用的所有目录和文件必须实际存在
2. **文件完整性** — 确认三个文件都已正确创建/更新：
   - 全局 `~/.claude/AGENTS.md`
   - 项目级 `./AGENTS.md`
   - 项目级 `./.gitignore`
3. **内容检查** — 确认无残留模板占位符、无引用不存在的路径

向用户展示验证结果汇总表。

## 全局 AGENTS.md 生成指南

当 `~/.claude/AGENTS.md` 不存在时，通过简短对话收集信息并生成。

### 需要了解的信息

向用户提问（一次问完，不要分多次）：

1. 你的主要技术栈是什么？（如：Spring Boot + Vue）
2. 你偏好什么代码规范？（如：阿里巴巴Java规范、Airbnb JS规范）
3. 有没有特别的偏好或工作习惯？（如：简洁回答、中文交流）

如果用户已经在对话中透露过这些信息（如本次对话中），直接使用已知信息，只需确认即可。

### 模板

```markdown
# Codex 全局指令

## 关于我
- {角色描述，如：全栈开发者}
- {核心关注点}

## 通用偏好
- {代码规范偏好}
- {框架/工具偏好}
- {交流风格偏好}

## Token 优化行为
- 接手新项目时，先看目录结构和构建配置了解概貌
- 每次只读取完成任务所需的文件，不扫描无关代码
- 复杂任务主动使用 Agent 工具委派给子 Agent
- 定期使用 /compact 压缩上下文
- 大型代码库优先通过 Grep/Glob 精确查找

## 安全与规范
- 敏感配置不写入代码
- SQL 操作优先使用参数化查询
- 安全配置不可跳过
```
